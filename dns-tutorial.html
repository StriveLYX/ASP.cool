🌐 DNS 域名解析入门教程

用最通俗的语言，从零开始理解域名解析。看完这篇，你就能独立配置 DNS 了。

第 1 章

什么是 DNS

🏠 通俗比喻：DNS 就是互联网的「电话簿」

想象一下，你要给朋友打电话。你知道朋友的名字叫「张三」，但电话不认识名字，你需要查电话簿找到他的号码 138xxxx1234，然后才能拨通。

DNS 做的事情完全一样：

你输入 apply.asp.cool → DNS 查询 → 找到 IP 地址 76.76.21.21 → 浏览器连接到这个 IP

为什么需要 DNS？

因为电脑之间通信用的是 IP 地址（比如 76.76.21.21），但人类记不住这些数字。所以我们用好记的域名（比如 apply.asp.cool），让 DNS 帮我们翻译。

你输入
apply.asp.cool
→
DNS 查询
域名 → IP
→
返回
76.76.21.21
→
浏览器访问
Vercel 服务器
💡 一句话总结

DNS = Domain Name System（域名系统），它的作用就是把「人类能看懂的域名」翻译成「电脑能看懂的 IP 地址」。

第 2 章

域名的结构

一个完整的域名由几个部分组成，从右往左读：

apply
子域名 (Subdomain)
.
asp
主域名 (Domain)
.
cool
顶级域名 (TLD)

每一层是什么意思？

部分名称例子说明
apply子域名apply、www、api、mail你可以自由创建，用来区分不同的服务
asp主域名asp、baidu、taobao你花钱买的那个名字，全球唯一
.cool顶级域名.com、.cn、.cool、.org域名后缀，由国际机构管理
🏠 再用餐厅比喻

假设你的餐厅叫「ASP」：

.cool = 餐厅所在的「美食街」（美食街里有很多餐厅）

asp = 你的「餐厅名字」（美食街里只有一家叫 ASP）

apply = 餐厅里的「包间名」（可以有 apply 包间、www 包间、api 包间）

你可以创建哪些子域名？

子域名可以随便起名，常见的有：

子域名完整域名通常用途
wwwwww.asp.cool主站（最常见）
applyapply.asp.cool报名/申请页面（你的项目）
apiapi.asp.cool后端 API 接口
mailmail.asp.cool企业邮箱
blogblog.asp.cool博客
@asp.cool根域名（不带子域名）
⚡ 关键概念：@ 代表什么？

在 DNS 配置中，@ 代表「根域名」本身，也就是 asp.cool（不带任何前缀）。

比如你直接访问 asp.cool，DNS 就会查找 @ 对应的记录。

第 3 章

记录类型详解

DNS 记录类型决定了「这条记录用来做什么」。最常用的有 4 种：

📝 A 记录（Address）

🏠 比喻：直接写上门牌号

「apply 这个包间在 216 号楼」—— 直接告诉客人具体的 IP 地址。

属性说明
作用把域名指向一个 IPv4 地址（如 76.76.21.21）
格式域名 → IP 地址（数字）
适用场景你知道服务器的具体 IP 地址时使用
限制IP 地址如果变了，你需要手动去改

例子：把 asp.cool 指向 IP 216.198.79.1

主机记录: @
记录类型: A
记录值:   216.198.79.1

🔗 CNAME 记录（Canonical Name）

🏠 比喻：告诉客人「去问前台」

「apply 这个包间？你先去问 Vercel 前台，前台会告诉你具体位置」—— 不直接给地址，而是让 DNS 去问另一个域名。

属性说明
作用把域名指向 另一个域名（不是 IP）
格式域名 → 另一个域名
适用场景使用第三方服务（Vercel、Cloudflare 等）时
优势对方 IP 变了不用你管，自动跟着变

例子：把 apply.asp.cool 指向 Vercel 的域名

主机记录: apply
记录类型: CNAME
记录值:   cname.vercel-dns.com

📋 TXT 记录（Text）

🏠 比喻：在门口贴一张告示

「这是 Vercel 的地盘，验证码是 xxx」—— 不影响访问，只是用来证明身份或传递信息。

属性说明
作用给域名附加 文本信息
格式域名 → 一段文字
适用场景域名验证、SPF 邮件防伪、SSL 证书验证
特点不影响网站访问，纯信息用途

例子：Vercel 要求你添加 TXT 记录来验证域名所有权

主机记录: _vercel
记录类型: TXT
记录值:   vc-domain-verify=asp.cool,6f52fc7e3c7a2e5bc05e

📧 MX 记录（Mail Exchange）

🏠 比喻：指定收发室

「所有寄给 asp.cool 的信件，请送到腾讯企业邮的收发室」—— 专门用来配置邮件服务。

属性说明
作用指定接收邮件的服务器
格式域名 → 邮件服务器地址
适用场景配置企业邮箱（如腾讯企业邮、阿里企业邮）
💡 你目前只需要关心 3 种

对于你的项目，只需要用到：A 记录（根域名）、CNAME 记录（子域名指向 Vercel）、TXT 记录（验证域名）。MX 记录以后配邮箱时再说。

第 4 章

主机记录是什么

主机记录就是子域名的「前缀部分」，它决定了这条 DNS 记录对哪个域名生效。

常见的主机记录值

主机记录对应的完整域名说明
@asp.cool根域名本身（直接访问 asp.cool）
wwwwww.asp.cool最常见的子域名，用于主站
applyapply.asp.cool你的报名页面
apiapi.asp.cool后端 API 接口
*所有子域名通配符，匹配所有未单独配置的子域名
_vercel_vercel.asp.cool以下划线开头的特殊记录，用于验证
🏠 比喻：餐厅的包间号

主机记录就是「包间号」：

@ = 大厅（直接进门就是）

www = 1号包间

apply = 2号包间

api = 3号包间

* = 「其他包间都走这个默认规则」

⚡ 为什么 _vercel 以下划线开头？

以下划线 _ 开头的主机记录是 DNS 的特殊约定，表示这条记录不会被用来访问网站，而是用于「验证」或「配置」目的。浏览器不会访问 _vercel.asp.cool，只有 Vercel 的服务器会去查询它。

第 5 章

A 记录 vs CNAME：什么时候用哪个？

A 记录

  • 直接指向 IP 地址
  • 适合：自己有服务器，知道 IP
  • 缺点：IP 变了要手动改
  • 根域名（@）只能用 A 记录

CNAME 记录

  • 指向另一个域名
  • 适合：用第三方服务（Vercel 等）
  • 优点：对方 IP 变了不用你管
  • 子域名推荐用 CNAME

简单判断规则

🎯 判断口诀

✅ 用 CNAME：部署在 Vercel / Cloudflare / GitHub Pages 等第三方平台

✅ 用 A 记录：部署在自己的服务器上，有固定 IP

✅ 根域名 @：用 A 记录（部分 DNS 服务商支持 ALIAS）

为什么你的 apply 要用 CNAME？

因为你的前端部署在 Vercel 上。Vercel 给你的不是一个固定 IP，而是一个域名 cname.vercel-dns.com。Vercel 可能有很多台服务器，会根据你的位置自动分配最快的那个。

如果用 A 记录指向某个 IP，万一 Vercel 换了 IP，你的网站就挂了。用 CNAME 就不会有这个问题。

⚠️ 注意：根域名的限制

按照 DNS 标准，@（根域名）不能使用 CNAME 记录。所以 asp.cool（根域名）只能用 A 记录指向 IP，而 apply.asp.cool（子域名）可以用 CNAME。

不过阿里云等部分 DNS 服务商支持「隐性 CNAME」或「ALIAS 记录」来绕过这个限制。

第 6 章

TTL 是什么

🏠 比喻：电话簿的「更新频率」

TTL = Time To Live（生存时间）。意思是：DNS 记录的答案会被「记住」多久。

如果 TTL = 10分钟，那么 DNS 服务器查到你的域名对应什么 IP 后，会把这个答案缓存 10 分钟。10 分钟内再有人的查询，直接返回缓存，不再去查。

TTL 值含义适用场景
10 分钟（600秒）改动后 10 分钟生效正在调试、经常改 DNS
1 小时（3600秒）改动后 1 小时生效一般网站
1 天（86400秒）改动后最多 1 天生效稳定运行的大型网站
⚡ 建议

你正在配置 DNS，建议先把 TTL 设为 10 分钟，这样改错了也能快速修正。等一切稳定后，再改回 1 小时或更长。

第 7 章

DNS 解析完整流程

当你在浏览器输入 apply.asp.cool 并回车后，背后发生了什么？

浏览器检查缓存
先看看自己之前有没有查过这个域名，如果有缓存就直接用。
查询本地 DNS 服务器
问你的运营商（电信/联通/移动）的 DNS 服务器：「apply.asp.cool 的 IP 是多少？」
查询根域名服务器
本地 DNS 不知道，就去问全球根服务器：「.cool 这个后缀归谁管？」→ 得到 .cool 顶级域服务器的地址。
查询顶级域服务器
问 .cool 服务器：「asp.cool 归谁管？」→ 得到 asp.cool 的权威 DNS 服务器地址（阿里云）。
查询权威 DNS 服务器
问阿里云 DNS：「apply.asp.cool 的记录是什么？」→ 返回 CNAME 到 cname.vercel-dns.com。
继续解析 CNAME
再查 cname.vercel-dns.com 的 A 记录 → 得到最终 IP 地址（比如 76.76.21.21）。
浏览器连接服务器
用拿到的 IP 地址，和 Vercel 服务器建立连接，加载你的网页。
💡 为什么 DNS 修改后要等？

因为上面的每一步都有缓存。你改了阿里云的 DNS 记录，但运营商的 DNS 服务器可能还记得旧的答案（在 TTL 过期之前）。所以 DNS 修改后通常需要 几分钟到几小时才能全球生效。

第 8 章

你的项目怎么配（实战）

现在回到你的 ASP.Cool 项目，来解释为什么每条记录要这么写：

实战配置

你的完整 DNS 配置表

主机记录类型记录值为什么这么写？
_vercel TXT vc-domain-verify=asp.cool,6f52fc7e3c7a2e5bc05e Vercel 要求的验证码，证明你是域名主人。验证完可以删。
apply CNAME cname.vercel-dns.com 你的前端部署在 Vercel，所以用 CNAME 指向 Vercel。访问 apply.asp.cool 就会打开你的网站。
www CNAME 79e70e2862e49dd1.vercel-dns-017.com www 子域名也指向 Vercel（之前配置的）。访问 www.asp.cool 也能打开网站。
@ A 216.198.79.1 根域名 asp.cool 指向一个 IP。这是之前的配置，暂时保留。

逐条解释

1️⃣ TXT 记录：_vercel

目的：Vercel 发现 asp.cool 之前绑在别人的账号上，所以需要你证明「这个域名是我的」。

原理：Vercel 让你在 DNS 里贴一张「告示」（TXT 记录），内容是它给的验证码。然后 Vercel 去查你的 DNS，看到告示上的验证码和自己生成的一样，就确认你是域名主人了。

验证后：这条记录可以删掉，不影响网站运行。

2️⃣ CNAME 记录：apply

目的：让 apply.asp.cool 指向你的 Vercel 网站。

为什么用 CNAME 不用 A：Vercel 有很多台服务器，IP 会变。用 CNAME 指向 cname.vercel-dns.com，Vercel 会自动帮你分配最快的服务器。

3️⃣ CNAME 记录：www

目的：让 www.asp.cool 也能打开你的网站。这条是之前就配好的，Vercel 自动生成了一个项目专属的域名。

4️⃣ A 记录：@

目的：让 asp.cool（不带 www）也能访问。目前指向一个 IP 地址。

✅ 配置完成后的效果

访问 apply.asp.cool → DNS 查到 CNAME → 跳到 Vercel → 显示你的网站 ✨

访问 www.asp.cool → 同样跳到 Vercel → 显示你的网站 ✨

第 9 章

常见问题

❓ DNS 修改后多久生效？

通常 10 分钟 ~ 48 小时。全球 DNS 服务器需要时间同步。你的 TTL 设为 10 分钟的话，大部分情况下 10-30 分钟就能生效。

❓ 怎么检查 DNS 是否生效？

在终端（命令行）输入：

# Windows
nslookup apply.asp.cool

# Mac / Linux
dig apply.asp.cool

如果返回了 Vercel 的 IP 地址，说明已经生效了。

也可以用在线工具：https://tool.chinaz.com/dns/（站长之家 DNS 查询）

❓ Vercel 提示 "Invalid Configuration" 怎么办？

通常是因为 DNS 记录还没生效。等几分钟再试。如果超过 1 小时还不行，检查记录值是否拼写正确。

❓ 可以同时有 A 记录和 CNAME 吗？

同一个主机记录不能同时有 A 和 CNAME。但不同的主机记录可以分别用不同类型。比如 @ 用 A 记录，apply 用 CNAME，这是完全没问题的。

❓ CNAME 记录值要带末尾的点吗？

在阿里云后台填写时不需要加末尾的点。系统会自动处理。

❓ 误删了记录怎么办？

DNS 记录可以随时重新添加，不会造成永久损坏。重新添加正确的记录，等 DNS 生效即可。
