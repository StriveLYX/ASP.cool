1. 什么是网站

一个网站本质上就是：用户通过浏览器访问 → 服务器返回内容。

🏠 通俗比喻

把网站想象成一家餐厅：

  • 前端 = 餐厅的装修、菜单、桌椅（用户看到的界面）
  • 后端 = 厨房 + 厨师（处理订单、做菜的业务逻辑）
  • 数据库 = 仓库（存放食材、记录库存）
  • 服务器 = 餐厅的物理建筑（一切运行的地方）
  • 域名 = 餐厅的地址（如南京路88号）

静态网站 vs 动态网站

静态网站动态网站
内容固定不变，所有人看到一样根据用户不同显示不同内容
例子个人简历页、产品介绍页淘宝、微信、抖音
技术只需 HTML + CSS前端 + 后端 + 数据库
复杂度⭐⭐⭐⭐⭐

2. 网站工作原理

当你在浏览器输入 www.taobao.com 时，背后发生了什么？

👤 你的浏览器
输入网址
↓ ① DNS 解析：把域名变成 IP 地址
🌐 DNS 服务器
taobao.com → 140.205.xx.xx
↓ ② 发送请求：浏览器向服务器要页面
🖥️ 服务器
接收请求，处理业务
↓ ③ 查询数据库：获取商品、用户等信息
💾 数据库
返回数据
↓ ④ 生成页面：服务器把数据组装成 HTML
🖥️ 服务器
返回 HTML 给浏览器
↓ ⑤ 浏览器渲染：把 HTML 变成你看到的页面
👤 你的浏览器
展示页面
💡 关键概念：HTTP 协议 浏览器和服务器之间用 HTTP 协议通信。就像"对话"一样：
浏览器说："请给我首页"（HTTP 请求）→ 服务器说："这是首页内容"（HTTP 响应）

4. 前端是什么

前端就是用户在浏览器里看到的一切：文字、图片、按钮、动画、布局……

前端三大核心技术

🏗️ HTML — 网页的"骨架"

定义页面上有什么内容（标题、段落、图片、按钮）

<h1>欢迎来到我的网站</h1>
<p>这是一段介绍文字</p>
<button>点击购买</button>
<img src="photo.jpg">

🎨 CSS — 网页的"皮肤"

定义内容长什么样（颜色、大小、位置、动画）

h1 { color: #0066ff; font-size: 32px; }
button { background: #0066ff; color: white; padding: 12px 24px; }

⚡ JavaScript — 网页的"大脑"

让页面动起来、能交互（点击按钮弹窗、提交表单、加载数据）

// 点击按钮时发送请求到后端
document.querySelector('button').addEventListener('click', async () => {
    const res = await fetch('/api/orders');
    const data = await res.json();
    // 在页面上显示订单数据
});

6. 前端实例：向服务器请求数据

前端最核心的能力之一就是与后端通信。使用 fetch() 发送请求：

// GET 请求：从后端获取数据
const response = await fetch('/api/courses');
const courses = await response.json();
// courses = [{id:1, name:"UI设计", price:299}, ...]

// POST 请求：向后端发送数据
await fetch('/api/orders', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ courseId: 1, plan: 'pro' })
});
💡 理解要点 前端只负责"展示"和"交互"，不直接操作数据库。所有数据都通过 API 向后端请求。

7. 后端是什么

后端是运行在服务器上的程序，负责：

  • 接收前端发来的请求
  • 处理业务逻辑（计算、验证、判断）
  • 读写数据库（存取数据）
  • 返回结果给前端

🏠 继续用餐厅比喻

前端是菜单，后端是厨房。客人（用户）看菜单点菜（前端发请求），厨房（后端）做菜（处理逻辑），从仓库（数据库）拿食材，最后端上菜（返回结果）。

后端框架对比

语言框架优点适合
JavaScript Express / Koa 和前端同语言，学习成本低 ✅ 推荐你学这个
Python Flask / Django 语法简洁，生态丰富 数据分析、AI 项目
Java Spring Boot 企业级，稳定可靠 大公司、银行
PHP Laravel 简单易上手 WordPress、中小网站

8. API 接口

API（Application Programming Interface，应用程序接口）就是前后端之间的"通信协议"。

API 的本质

API 就是一个URL 地址 + 约定的请求格式：

// 前端发送请求：
GET  /api/courses              // 获取所有课程
GET  /api/courses/1            // 获取ID为1的课程
POST /api/orders               // 创建订单
POST /api/alipay/pay           // 发起支付宝支付
POST /api/alipay/notify        // 支付宝回调通知

// 后端返回 JSON 格式的数据：
{
    "id": 1,
    "name": "UI设计实战",
    "price": 299,
    "students": 3200
}

HTTP 请求方法

方法作用类比
GET获取数据查看菜单
POST创建数据下单
PUT更新数据修改订单
DELETE删除数据取消订单

9. 后端实例（Node.js）

下面是一个最简单的后端服务，只有 30 行代码：

// server.js — 最简单的后端服务
const express = require('express');  // 引入框架
const app = express();             // 创建应用

// 接口1：返回课程列表
app.get('/api/courses', (req, res) => {
    res.json([
        { id: 1, name: 'UI设计实战', price: 299 },
        { id: 2, name: '平面设计',   price: 199 },
    ]);
});

// 接口2：创建订单
app.post('/api/orders', (req, res) => {
    const { courseId, plan } = req.body;
    // TODO: 保存到数据库
    res.json({ success: true, orderId: 'ORD20260416001' });
});

// 启动服务，监听 3000 端口
app.listen(3000, () => console.log('服务已启动: http://localhost:3000'));

10. 数据库是什么

数据库就是一个有组织的文件柜，用来高效地存取和管理大量数据。

📊 通俗理解

Excel 表格就是一个最简单的"数据库"——有行有列，可以筛选排序。真正的数据库（如 MySQL）做的事情一样，只是更快、更强大、支持多人同时操作。

为什么需要数据库？

  • 持久化：程序重启后数据不丢失（内存中的数据会丢失）
  • 并发安全：1000人同时下单不会冲突
  • 高效查询：百万条数据中秒级查找
  • 关联查询：用户→订单→商品，表与表之间可以关联

数据库类型

类型代表特点适合场景
关系型 MySQL、PostgreSQL 用表格存数据，支持 SQL 查询 ✅ 大多数网站
文档型 MongoDB 用 JSON 格式存数据，灵活 内容管理、日志
键值型 Redis 极速读写，常做缓存 验证码、排行榜

11. SQL 基础

SQL（Structured Query Language）是和数据库"对话"的语言。

四大核心操作（CRUD）

-- 1. CREATE（创建）：新建一张表
CREATE TABLE users (
    id       INT PRIMARY KEY AUTO_INCREMENT,  -- 用户ID，自动递增
    name     VARCHAR(50) NOT NULL,              -- 用户名
    email    VARCHAR(100) UNIQUE,             -- 邮箱（唯一）
    plan     VARCHAR(20) DEFAULT 'free',  -- 会员方案
    created  DATETIME DEFAULT NOW()        -- 注册时间
);

-- 2. INSERT（插入）：添加数据
INSERT INTO users (name, email, plan) VALUES
    ('张三', 'zhangsan@qq.com', 'pro');

-- 3. SELECT（查询）：获取数据
SELECT * FROM users WHERE plan = 'pro';      -- 查所有专业版用户
SELECT name, email FROM users ORDER BY created DESC; -- 按注册时间倒序

-- 4. UPDATE（更新）：修改数据
UPDATE users SET plan = 'ultimate' WHERE id = 1;

-- 5. DELETE（删除）：删除数据
DELETE FROM users WHERE id = 1;
⚠️ 重要原则 后端代码中永远不要拼接 SQL 字符串（有注入风险），应使用参数化查询。

12. 后端连接数据库实例

const mysql = require('mysql2/promise');

// 创建数据库连接池
const pool = mysql.createPool({
    host: 'localhost',
    user: 'root',
    password: 'your_password',
    database: 'asp_cool'
});

// 在 API 中查询数据库
app.get('/api/users', async (req, res) => {
    const [rows] = await pool.query('SELECT * FROM users');
    res.json(rows);
});

14. 域名与 SSL

域名

域名就是网站的"网址"，比如 apply.asp.cool。

  • 注册：在阿里云/腾讯云/GoDaddy 等平台购买（¥30-100/年）
  • 解析：把域名指向服务器的 IP 地址（DNS 记录）
  • 备案：国内服务器需要 ICP 备案（约 1-2 周）

SSL 证书（HTTPS）

让网址从 http:// 变成 https://（小锁图标），数据传输加密。

  • 免费：Let's Encrypt（推荐）、阿里云免费证书
  • 付费：各大云厂商 SSL 证书
  • 支付回调必须用 HTTPS

15. Nginx 反向代理

Nginx是一个"交通指挥员"，负责：

👤 用户浏览器
访问 apply.asp.cool
↓
🚦 Nginx (端口80/443)
接收请求，转发给后端
↓ 转发到 localhost:3000
🖥️ Node.js 后端 (端口3000)
处理业务逻辑
# nginx.conf — Nginx 配置文件
server {
    listen       443 ssl;
    server_name  apply.asp.cool;

    # SSL 证书
    ssl_certificate     /etc/ssl/asp.cool.pem;
    ssl_certificate_key /etc/ssl/asp.cool.key;

    # 反向代理：把请求转发给 Node.js
    location / {
        proxy_pass http://localhost:3000;
        proxy_set_header Host $host;
    }
}

# 方法1：用 Git（推荐）

# 方法2：用 SCP 直接传文件
scp -r ./server root@your-server-ip:/home/app/

步骤 4：启动后端

cd /home/app/server
npm install
pm2 start server.js --name "asp-cool"
pm2 save               # 开机自启

步骤 5：配置 Nginx

sudo vim /etc/nginx/sites-available/asp.cool
# 写入上面的 Nginx 配置
sudo ln -s /etc/nginx/sites-available/asp.cool /etc/nginx/sites-enabled/
sudo nginx -t          # 检查配置
sudo systemctl restart nginx

步骤 6：域名解析

在域名服务商后台添加 A 记录：apply.asp.cool → 你的服务器IP
