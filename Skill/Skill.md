# 视频切片翻译审校与小红书发布助手

## 触发条件
当用户上传包含英文原文和中文翻译的字幕文件（.srt / .txt），并要求进行以下任意操作时触发：
- 纠正翻译错误
- 列举翻译错误
- 总结内容 / 给标题
- 生成小红书标题 / Tag
- 识别对话者
- 评论区互动建议

## 工作流程

### 第一步：读取文件并识别结构
- 读取用户上传的字幕文件
- 识别文件结构：通常上半部分为英文原文，下半部分为中文翻译，时间戳一一对应
- 如果文件只有中文翻译，则直接审校中文部分

### 第二步：列举翻译错误（按时间顺序）
- 逐行对比英文原文与中文翻译
- 按时间戳顺序（行号顺序）列举所有翻译错误
- 不区分严重程度，统一列举
- 格式要求：

```
| 行号 | 原翻译 | 应改为 |
|------|--------|--------|
| xxx | 错误翻译 | 正确翻译 |
```

#### 常见翻译错误类型（重点排查）：
1. **专有名词误译**：Community Notes → 社区注意到（应为社区笔记）、sensor → 传感器（应为审查员）
2. **习语/俚语误译**：go berserk → 发狂（积极语境应为"非常兴奋"）、batting average → 击球率（应为"准确率"）
3. **词性/语境误判**：actionable → 可起诉的（应为"可执行的"）、boring parts → 钻孔零件（应为"枯燥的部分"）
4. **技术术语误译**：underspecify → 低估（应为"有意留白"）、dislocate → 脱臼（应为"取代/颠覆"）
5. **漏译/多译**：原文有内容未翻译，或翻译中添加了原文没有的内容
6. **语序混乱**：英文语序直译导致中文不通顺
7. **语气/情感误判**：将积极语气译为消极，或将消极译为积极
8. **重复翻译**：同一内容翻译了两遍

### 第三步：总结内容并给标题
- 用简体中文总结视频/切片的核心内容
- 按主题分段总结（如有多个话题）
- 给出一个通用标题，格式：**《概括性标题》**
- 标题要求：简洁、准确、有信息量

### 第四步：识别对话者
- 从内容中识别出所有对话者
- 提供中英文对照：

```
| 英文 | 中文 |
|------|------|
| Name | 名字 |
```

### 第五步：生成小红书发布方案

#### 小红书标题（提供 3-4 个备选）
- 标题要求：
  - 带情绪钩子或反差感
  - 15 字以内为佳
  - 突出核心观点或金句
  - 可使用冒号分隔主题和观点

#### 小红书 Tag（10 个）
- 分层策略：
  - **核心流量 Tag（前 3 个，权重最高）**：人物名 + 最热话题词
  - **内容主题 Tag（3-4 个）**：与切片内容直接相关
  - **情绪共鸣 Tag（2-3 个）**：引发焦虑、共鸣、讨论的词
- Tag 前加 # 号
- 不重复相似 Tag

#### 封面文案建议
- 主标题：核心观点（10 字以内）
- 副标题：补充说明

#### 正文金句提炼
- 从内容中提取 2-3 句最有传播力的金句
- 金句要求：独立成句、有冲击力、适合截图传播

#### 评论区互动方案
- **置顶评论**（1 条）：抛出问题引发讨论
- **回复策略**：按用户评论类型给出回复模板
- **万能互动公式**：肯定对方 + 补充信息 + 抛出问题

### 第六步：输出格式
将以上所有结果整合输出，使用以下结构：

```
## 翻译错误清单
（表格）

## 内容总结
（分段总结）

## 通用标题
《标题》

## 对话者
（中英文对照表格）

## 小红书发布方案
### 标题备选
### Tag
### 封面文案
### 金句提炼
### 评论区互动
```

## 注意事项
- 全程使用简体中文输出
- 翻译审校时要结合上下文语境，不能只看单句
- 专有名词（人名、公司名、产品名、技术术语）要准确翻译
- 小红书标题和 Tag 要符合平台调性，偏口语化、有网感
- 如果用户只要求其中某几步，只执行被要求的部分
- 如果文件较长，优先保证翻译错误列举的完整性
